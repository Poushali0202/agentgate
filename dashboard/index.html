    A guide to your control room

    Understand every stop, check, and green light.

    AgentGate checks the request, then the purchase behavior. A recognized agent can still make an unusual purchase.

    01

    Check the agent

    A digital signature helps detect changed, expired, or repeated requests. This demo uses a mock key directory; it does not establish a person's legal identity.

    02

    Check the purchase

    Rules look for unusual volume, bulk orders, shared payment references, and changes from the customer's purchase history.

    03

    Choose the next step

    Allow ordinary requests, ask the customer about uncertain ones, and stop requests that fail the checks.

    What the colors mean

    Green · Allowed
    The gateway let the request proceed. This does not prove payment settlement.
    Amber · Confirmation
    The gateway asks for a human decision. A challenge entry alone does not show whether approval is still pending.
    Red · Blocked
    The gateway stopped the request. The recorded reason explains which check failed; it does not prove criminal intent.

    Reading the numbers

    Decision snapshot
    Up to the latest 100 logged decision records. Approval and denial updates are separate records, so this is not a count of unique purchases or customers.
    Risk, from 0 to 100
    A rule-based score, not a percentage chance of fraud. Higher means more recorded warning signals. Verification failures and customer-change rules also affect the outcome.
    Typical check time
    The median gateway processing time in the loaded records. It excludes human response time and internet travel time.
    95th-percentile check time
    95% of the gateway checks in the full stored log finished at or below this time. Human response time is excluded.
    Unresolved log entries
    Challenge records without a matching resolution in the latest 100 entries. Older updates or a server restart can make this differ from the actual Guardian queue.
    Detection quality
    Precision, recall, and false alarms describe labeled simulator traffic. They are not independently measured real-world fraud rates.
    Millisecond correlation
    Shared-card or shared-address activity across at least three agent keys in a 100 ms window. This is historical evidence, not an automatic block or proof of coordination.

    What is simulated?

    The signatures and gateway decisions are real. The key directory, consumer references, card fingerprints, and labeled attack scenarios are demo inputs. The hijack switch is staged. The scanner is pattern-based; a low-risk page is not guaranteed safe.
